## 1. What it is for

K15 moves the ELF loader to the creator, which then maps its own segments, so the
kernel can no longer say "I loaded this image". Instead the kernel measures:

1. an image VMO is **sealed**, immutable from then on, with its digest computed by
   the kernel at sealing;
2. **a process's executable mappings come only from sealed, measured VMOs**;
3. **the process carries the digests of its images**, readable by whoever holds it;
4. **a grant that needs a certified driver is checked against the certified list**.

So a partition manager or devmgr can be lied to by nothing: the digest it reads is
the kernel's. What the digest says is certified is `A.FIRMWARE`'s (§6).

## 2. Sealing

**`VMO_EXECUTABLE(vmo, VMO_SEAL)`** (0x1027, K2's reserved second register, new
value 1). It takes a handle with `READ | MAP | WRITE`. `WRITE` is required so that
a holder of a read-only handle cannot freeze someone else's writable memory. It
replaces the handle as plain `VMO_EXECUTABLE` does, answering one with `EXECUTE`
and without `WRITE`, keeping the rest. Then:

* **Only plain anonymous VMOs.** Refused `NOT_SUPPORTED` if pager-backed, a file's,
  physical, coherent, combining or holding a kernel view. A coherent or physical
  VMO's bytes can change under the kernel's feet by DMA or by the device.
* **Refused `BAD_STATE`** while any region by handle has a ceiling holding `WRITE`
  (`Vmo::writable_regions`, fork's copies included, K14.2: `shared_may_write` counts file
  mappings alone), while any file mapping may write, while **any** hold is live (a hold
  has no recorded direction, so a live one cannot be proved a read; K14.3), or while a
  frame has a second reference (`Vmo::fork` shares frames). The count changes only under
  `pages`, so a seal and a map cannot pass each other, and it falls in **phase three of an
  unmap** (`give_back`, after that unmap's shootdown), so no stale writable translation
  outlives it. A seal's holder of `WRITE` freezes the VMO for its other holders too:
  accepted (K14.9).
* **The order: commit, freeze, hash, store, replace the handle (K14.9).** Every absent page
  is committed as zeros under the job's charge (`NO_MEMORY`, nothing sealed). `Pages.sealed`
  is set under `pages`'s lock with room for the frame list had first. The hash takes no lock
  and no memory, over `len_bytes (u64 LE) || page 0 || page 1 ...` with `ferrix-sha256`, then
  stores the result. **After the freeze nothing can fail or wait**: a kill takes effect on
  return to user, so no object stays sealed and unhashed. Preemptible; a check holds that
  no preempt count is held (K14.10). `SEAL_MAX_PAGES` (64 MiB) is refused `INVALID_ARGS`;
  an image over it fails its build, not silently here (K14.10). The time is measured per
  architecture for MEMORY-AND-TIMING, armv7a included.
* **Two sealers.** The second takes `BAD_STATE`. During the hash `VMO_DIGEST` answers
  `SHOULD_WAIT` (a read never blocks) and an executable map `BAD_STATE`, so nothing runs an
  image before its measurement exists. **`VMO_WRITE` on a sealed VMO answers `BAD_STATE`**
  (K14.9), and so does a writable map.

Sealing is irreversible and the kernel holds no unseal. A sealed VMO's frames are
released when the last reference goes, as any VMO's.

**In-kernel sealing.** `Vmo::seal` is the same function for the images the kernel itself
reads from the initramfs (`BOOT-AUTHORITY.md`), and for driver images in DEVICES under
`personality=user`, whose handles are `READ|TRANSFER`, so that devmgr cannot seal them
(K14.12).

### 2.1 Every write path, tagged

**Every `pages.lock()` in `vmo.rs` carries a tag on the line before it (K14 Q1):**
`// SEAL: refused` (the site tests `sealed`), `// SEAL: read`, or `// SEAL: sourced, why`
(only an object with a source reaches it, and no seal takes one).
`check-vmo-seal-tags.py`, in `xtask check`, fails on a lock with no tag and on a `refused`
tag with no test after it, with a planted control, so K3's and K13's future paths cannot
miss it. No new type.

`Vmo::hold` has a direction now: `hold` is refused on a sealed VMO; `hold_read`, which
`VMO_PIN` with `PIN_READ_ONLY` takes on a sealed VMO, holds its frames as they are (a sealed
frame is never written, so a sharer's copy on write reaches nothing of it).

**Frames handed out.** `page()` and `Held::frames()` hand out frame numbers. Their kernel
writers are the cores with a kernel view (audio, display, block and net rings, render),
refused at the seal and after it; `sigpage` and `vdso` hold objects of their own that are
never sealed. **Machine check**: `take_poisoned` takes only a file's clean copy (sourced), so
a poisoned page of a sealed VMO stays, and a later read reports it as for any anonymous
page. **The scrubber** reads and never writes. The fault path has no read-only leaf to upgrade:
no region over a sealed VMO has a writable ceiling.

### 2.2 Copy-on-write

`Vmo::fork` of a sealed VMO: allowed, and the child is an ordinary unsealed anonymous
VMO; the frames are shared read-only and the child copies on write. Since a sealed
VMO's frames are never written through the parent, K2's F-41 check still holds. A VMO
that has shared frames *in* from a fork, or out to a fork, at the moment of the seal:
refused `BAD_STATE`. Frame reference counts above 1 are the test, so no history is
kept. A forked child, unsealed, has no digest and can never map executable in a
measured space.

**A seal's time (K14.10, ledger 6181 D.8).** Stage 9 prints a megabyte's time. On the gate pool, loaded: x86-64 under KVM 4.9 ms, so about 310 ms for `SEAL_MAX_PAGES`; under TCG 28.4 ms, emulated; AArch64 under TCG 18.2 ms, emulated; ARMv7-A under TCG 19.2 ms, emulated. **Emulated figures set no bound**, and a loaded pool's KVM figure is an upper reading of one boot. The bound on real processors is a BACKLOG row, owed before a profile relies on it; no product path seals until the boot authority lands.

## 3. Executable only from sealed

**`measured` is a sticky field on the space (K14.7)**, set once, never cleared, copied by
`SPACE_CLONE`. `may_execute` reads no job: a job read under the space's spin lock takes the
membership lock, the nesting ledger's PR #40 B1 refused. A **job** carries `measured` too,
set once by `JOB_CREATE`'s `JOB_MEASURED` option (`1 << 8`) and inherited by every job made
inside it. What ties them: `SPACE_CREATE` by a measured caller makes a measured space;
`PROCESS_CREATE` into a measured job measures the new process's space before it starts; and
**`move_charged` (`cgroup.procs`) refuses a process crossing the measured line, both ways**
(`process_create`'s own placement aside). A K11 swap of a process's space keeps the record:
what ran stays recorded.

| Operation | In a measured space | Id |
|---|---|---|
| `SPACE_MAP` with `MAP_EXECUTE`, or with a handle carrying `EXECUTE` (the ceiling: no later protect finds an unmeasured region to raise) | only from a sealed VMO with its digest stored, else `BAD_STATE`. `EXECUTE` on both handles still required (K2) | L.mm.117 |
| `SPACE_ALLOCATE` with `MAP_EXECUTE` | refused `BAD_STATE`; its regions' ceiling holds no `EXECUTE` | L.mm.118 |
| `SPACE_PROTECT` to `MAP_EXECUTE` | only a region whose ceiling holds `EXECUTE`, which only a sealed map has, else `BAD_STATE` | L.mm.119 |
| plain `VMO_EXECUTABLE` (no seal) by a measured caller | refused `BAD_STATE` | L.mm.120 |
| `PROCESS_CREATE` with an image VMO, until K15 | only a sealed image; its digest is recorded | L.mm.121 |
| `SPACE_CLONE` by a measured caller of an **unmeasured** source | refused `BAD_STATE` (K14.6), since the clone would hold unsealed executable regions. A clone keeps its source's state | L.mm.122 |
| a Linux `mmap`/`mprotect` with `PROT_EXEC` (`personality=kernel`) | not reachable: the load's starter places nothing in a measured job, and a `cgroup.procs` move refuses | L.mm.126 |
| **the vDSO and the ARMv7-A sigpage** (K14.5) | `map_shared_code` and `map_code_page`'s objects are the kernel's, under `A.FIRMWARE`, built at run time with a live data page, so they cannot be sealed. They carry `Ceiling::Kernel`, stay out of `images`, are exempt from `may_execute` by that named path, and no user handle reaches it | L.mm.123 |

**Audit (K14 Q2).** A refusal is `BAD_STATE`, not `ACCESS_DENIED`, so `record_call`'s funnel
writes no false RIGHTS record, and it writes its own event, `UNMEASURED`, with the call's
number. No record for a seal.

**Which jobs are measured, by profile.**

* `personality=kernel` (`present`, `desktop`): none unless asked by `JOB_MEASURED`, which only
  the boot check does. Boots are unchanged but for the check's own line.
* `personality=user`: the kernel measures the three first jobs (`BOOT-AUTHORITY.md`).
  **A Linux program's restricted space (K11) is the one exception**: it runs other people's
  code, JITs and dlopen'ed files, so measuring it means nothing. K11's creation call leaves it
  unmeasured, and the grant (§5) treats any process with a restricted space as unmeasured,
  since its code makes no native call through the shared table (K11's rule, to be named by id
  when K11 lands; K14.8). **A K17 level above QM implies measured**, refused otherwise, with
  a check, when K17 lands (Q4, K14.8). `linuxd`'s own normal-mode space is measured. Until K11
  lands no restricted space exists.

ASR-2 (W^X) is untouched; `may_execute` is on top of K2's two layers.

## 4. The process carries its digests

`Images`: a fixed block of `MAX_IMAGES` = 32 digests, deduplicated, boxed once and **had before
the space's lock** (K14.11: no growth under it; a fixed block, for K16). A map past it is refused
`LIMIT_REACHED`. `SPACE_CLONE` copies it. An unmap does not remove a digest: **what ran stays
recorded** (L.mm.124).

**`VMO_DIGEST` (0x10C1): `(vmo, *out)`**, `READ`: the 32 bytes. `BAD_STATE` when not sealed,
`SHOULD_WAIT` during the hash.

**`PROCESS_IMAGES` (0x10C2): `(process, *out, capacity)`**, `MANAGE`, on a process made through
the native ABI: copies up to `capacity` digests and answers how many there are. When the space is
not measured, the answer has **`IMAGES_UNMEASURED` (the word's second-highest bit)** set, so a reader cannot take a
partial list for a whole one (L.mm.125). `Rights::PROCESS`'s comment still holds: this is the
kernel's record, not the process's memory. 0x10C3 is released (K14.11).

## 5. The certified list and the grant (revised for K14.1; back to the consultant before code)

**The list.** `.ferrix/certified` in the initramfs: magic, version, count, then `count` ×
(digest 32 bytes, name 32 bytes), at most 256. Read by the kernel once, at the first-image stage,
into a boot-sized block, parsed with stated bounds (host-tested, fuzzed). **A malformed file is an
empty list and a line, never a boot stop**; `present` and `desktop` have no file and no line; xtask
writes it only for a profile with certified items, its framing (`len || pages`, zero-padded)
host-tested against the kernel's (K14.12). `A.FIRMWARE` is extended over the list.

**What the grant vouches for.** Code bytes are not a process (K14.1). A process **passes** when:

1. every digest on its space's record is on the list, there is at least one, and its space is
   measured and has no restricted space;
2. **its starter passed, or was the kernel**: `Control` records `grant_starter: bool` at
   `PROCESS_CREATE` (the kernel's first images: true; otherwise the caller's own pass). devmgr, not
   certified, cannot pass a process: on a certified profile only the partition manager or the
   kernel starts a driver of a `needs_certified` node, which reconciles MICROKERNEL §6.5's "devmgr may
   grant" (line 835: **to be changed to "the starter may grant"**) with §6.3's "devmgr not certified";
3. **no one reached in**: any by-handle change to its space after its start (`SPACE_MAP`,
   `SPACE_PROTECT`, `SPACE_WRITE`, `SPACE_UNMAP`, from a handle `process_space` gave before it) sets
   `tainted`, sticky, on the space, and a tainted space never passes;
4. **no one controls it**: its job's and its ancestors' supervisors (K4) are held by a passing
   process or none: an exception channel can rewrite registers, so a supervisor outside the set is
   control of the driver. Attaching one to a job with a passed process afterwards is refused.

**After a first grant**, `granted` on the space is set: a map of a digest not on the list is refused
(`BAD_STATE`, `UNMEASURED`), and any by-handle change from another process is refused rather than
tainting. **Objects from a `needs_certified` node** (vector, I/O mapping) are minted without
`TRANSFER`, so that a passing driver cannot hand them on; a pin already has none.

**Which nodes (K14.4).** `needs_certified` = **certified profile and `reaches_memory()` and
untranslated**, on any architecture: K8.3's admission, set at publication, before any handle exists.
G4 took armv7a out of the claim after X1, so **the default set on armv7a is empty today** (its
profiles carry no level). X1's "DMA-capable, classified per platform" is met by over-approximation:
every node but the two the kernel synthesises (`L.device.57`), so the STM32MP1's DMA and MDMA are in
it, shown by a sweep check. The partition manager's statically assigned devices: each flagged by its
description. `present`: none but the check's made-up node.

The partition manager also reads `PROCESS_IMAGES` itself and compares with its description's
digests (stricter: exactly that image).

**Rejected**: passing a process on its bytes alone (K14.1's three routes).

## 6. Rules and requirements

**H.MEM.29**: *a sealed VMO's contents and length never change after its seal, and its digest
is the kernel's, computed from its frames after the freeze.*

**H.MEM.30**: *a measured space's executable memory comes only from sealed, measured VMOs and the
kernel's own code pages; the space's digests are recorded, and never removed.*

**H.MEM.31** (§5, not written until the grant's review): *a grant that needs a certified driver
is refused when any digest is not on the certified list.*

| Id | Rule | Check (`object::sealing_check`, stage 9) | Control |
|---|---|---|---|
| L.mm.111 | seal: only plain anonymous; refused for pager, file, physical, coherent, combining, kernel view; needs `WRITE` | coherent, kernel view, read-only handle refused | the kind test removed: *a coherent VMO was sealed* |
| L.mm.112 | seal refused while a writable-ceiling region, a file mapping that may write, a live hold or a shared frame stands | each; and once unmapped it passes | the count's test removed: *a writably mapped VMO was sealed* |
| L.mm.113 | every write path refused after a seal; the bytes unchanged | `VMO_WRITE` and writable map through a kept handle; `write_page`, `commit_and_write`, `zero_from`, decommit, `hold`, the `make_*` calls | a `refused` site's test removed: *a sealed VMO was written*; `check-vmo-seal-tags.py`'s own planted untagged lock |
| L.mm.114 | the digest is SHA-256 of length and frames, against a vector computed apart; a differing byte differs | one zero page, one with a byte | the hash fed no length: *a seal's digest differs from the known vector* |
| L.mm.115 | no digest and no executable map between the freeze and the store | `freeze_for_check` | the digest's test removed: *an image mapped executable before its digest existed* |

## 7. What moves in the evidence

* `ferrix-sha256` is in the **item** ring today (`certification-item.json`, the signing
  verifier's). The core now names it (`vmo.rs`), so it moves to the **core** ring, which ledger
  5745 (K14.13) is the citation for: its tests and FIPS vectors are its verification, and it has
  no `unsafe`, no allocation, no dependencies.
* MEMORY-AND-TIMING: the seal's hash (no lock, bounded by `SEAL_MAX_PAGES`, preemptible);
  the digest list's bound; the image-list lock's hold (one bounded push).
* ST §9.2 and SAFETY-MANUAL: a new AoU for the integrator's certified list, and K2's
  §2.4 alias (b) stated as closed for measured jobs.
* VULNERABILITY-ANALYSIS: SHA-256's collision resistance as the assumption; the digest
  covers bytes, not behaviour (a certified image given bad inputs is its own
  requirement's problem); time of check is not an issue because seal is immutable.
* `SECURITY-TARGET`: FPT_TST-like self-test wording is not claimed: this measures
  images, it does not attest the kernel itself.

## 8. Depends on

K2 slice A (`VMO_EXECUTABLE`, `SPACE_MAP`) and `Rights::EXECUTE`, on `mk-resolve`.
K15 is complementary: the design works before it (`PROCESS_CREATE` with a sealed image)
and after it. K11's `restricted` flag and K17's level are read, not built here: until they
land, no space is restricted and every level is QM, so the exception is unreachable.
When K17 lands, "a level above QM" reads `level_declared(job) && job.level() > 0`: under
K17 a job that never asked sits at the top level, undeclared, and is not to be refused.
