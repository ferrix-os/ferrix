# K13: the rebind contract

**Design, 2026-11-04 (mk-m2). Reviewed: OK IF (1) to (9), ledger 5968, folded in here.** `docs/MICROKERNEL.md` §3,
row K13, and `OPAQUE-KERNEL.md` §2 point 6, generalised to user space: *a server's restart
without its clients' loss: a pager VMO handed to the next instance of its server, parked
state charged to its clients' jobs (ledger 36). `linuxd` itself is not rebound: a `linuxd`
that dies takes its partition's programs with it.*

Ids: **H.OBJ.28**, **L.object.300-305, 307**. Calls **0x10A2 `PAGER_KEEP`**, **0x10A3
`PAGER_TAKE_UP`**. Panic code **FX-0935** (`STAGE9_REBIND`). One stage 9 line, **`rebind`**,
after `pager`. Estimate: **10 points**. Dark for today's profiles: no server asks for it; a
mechanism with its own boot check. T0's per-kind park in ring 0 stays for the hybrid.

## 1. What needs the kernel, and what does not

| State a client has with a server | Survives the server's death how | New in the kernel? |
|---|---|---|
| A channel | The server's supervisor holds a duplicate of the server's end (`Rights::CHANNEL` has `DUPLICATE`), so the peer does not close; queued messages stay, charged as they were (F-37, to their writers); the next instance gets the end. **So a message the dead server had already read is gone and its client hears nothing: a client with no deadline waits on. That is the supervisor's assumption of use (5968 (5)): it tells such a client, or the protocol carries a deadline; M8's row kills a server holding a read request** | no |
| A VMO a server shared | The object lives while anyone holds it; the supervisor keeps a duplicate for the next instance, as it keeps an image | no |
| An interrupt, I/O mapping, device | Held and handed by the supervisor today (`devmgr`); K8 | no |
| A K7 ticket a dead server adopted | Ends with the request or channel it is tied to | no |
| **A pager-backed VMO with faults outstanding** | Today the pager's one handle closing **fails every request** (K3.md §2.8): the client gets `SIGBUS` | **yes: K13** |

So K13 is small by design (the customer's *keep the kernel slim*): one object, two calls, and
the rest is a protocol between a supervisor and its server, which `DRIVER-MODEL.md`'s T0
restart already is.

## 2. The mechanism

* **`PAGER_KEEP(pager) → keeper`.** A second, distinct handle kind on the pager's core,
  `Rights::KEEPER` = `MANAGE | TRANSFER`, no `DUPLICATE`; at most one per pager
  (`ALREADY_BOUND`). It needs `PAGER` on the pager handle. One object and the registry's heap
  charged to the job of the caller (5968 (2)(b)): that keeps the core's registry charged while
  parked. If a server asks and passes it on, its job stays charged after it dies, as for any
  object it made and gave away; the job's slot is held, and a removal of the job proceeds as for
  those. A supervisor that makes the pager itself and transfers the handle pays itself. K3's rule stands: there is one pager
  handle, its close the pager's death; a keeper changes what that death does.
* **The pager's close, with a keeper**: the pager is **parked**. No request ends. New faults
  open requests as ever, which are listed and **not sent**, and every wait stays bounded by the
  pager's own bound (H.MEM.22 unchanged, never longer than `PAGER_WAIT_MAX`), so a server that
  takes too long costs the client `SIGBUS`, never a hang, and a parked pager can never hold a
  faulting process past that bound. Present pages stay usable. One `PAGER` audit record.
* **`PAGER_TAKE_UP(keeper, port) → pager`.** `MANAGE` on the keeper, `WRITE` on the port;
  `BAD_STATE` unless parked. Allocates first (a promise per outstanding request, with the lock
  let go, as `list_or_join` grows, 2858 (2)); if requests outnumber promises at the lock it lets
  go and grows; `NO_MEMORY` leaves it parked and a retry works. Then under the registry's lock it
  installs the port and clears parked, then queues one `PACKET_PAGE_REQUEST` per open request
  **with its own id**, after the lock is let go, and the old port's reference drops outside it.
  Answers a new pager handle, `Rights::PAGER_OBJECT`, charged to the caller. Each waiter's bound
  was set in `wait()`, so nothing restarts. A promise is capacity in the port's queue, as K3's
  every promise: charged to nobody, bounded by the open requests, each with a record charged to
  its own job (5968 (2)(a)).
* **The keeper's close**: if parked, this is the pager's death, as K3.md §2.8 ("Pager gone").
  If live, the pager simply has no keeper again.
* **One state, one lock** (5968 (1)): live, parked and dead are one field under the registry's
  lock, decided by the pager's close, the keeper's close and the take-up alike, so no order
  leaves a pager parked with no way out. **A generation** guards the race: a fault takes no
  promise while parked, and lists itself only if the generation it read is current, or goes round.
  A packet sent to the old port after a take-up is harmless: its request is already re-sent. With
  the same port handed back, a second packet is possible and harmless too (5968 (4)): a supply
  skips a present page (K3.md §2.7), `PAGER_OP_DIRTY` is idempotent, and an answer to an ended
  request finds nothing.
* **Audit** (5968 (6)): a `PAGER` record, `Outcome::Done`, at a park (the kernel's subject) and at
  a take-up (the taker's, with the requests outstanding), since a take-up grants authority over
  the pager's clients.
* **Who pays.** A request's record and port room are the faulting job's (K3.md §2.2), held by
  the request, parked or not: that is ledger 36's "parked state charged to its clients' jobs".
  Pages stay charged to whoever paid. The keeper is the supervisor's. **So parking creates no
  uncharged pool**, and it is bounded: a parked request holds a waiting task, as a live one does.
* **Dirty state survives** in the VMO (K3.md §2.5): a page written before the death stays Dirty
  and is reported by `PAGER_QUERY_DIRTY` to the next instance. An awaiting-clean page is
  reported as such, so the next instance writes it back again; never lost.
* **`linuxd` is not rebound**: nothing in K13 hands a process a program's state, and the
  partition's programs die with it (§2.3's first row). K13 serves `btrfsd` and device servers.
* **Certified partitions** (K17 (d), §5's AoU): a keeper is authority over a pager a safety
  partition may have chosen, so its level is the pager's.

Lock order: K3.md §2.9, unchanged; the port is read under the registry's lock.

## 3. Rules

**H.OBJ.28** (parent O.ISOLATE): *A pager with a keeper whose handle closes shall hold its
outstanding requests until `PAGER_TAKE_UP`, which shall send each again to the new port under its
own id, or the keeper's close, or each waiter's bound, whichever comes first; present pages and
their Dirty state shall stay; and everything held meanwhile shall stay charged to the job that was
charged for it.* Cases beyond the table's: a `DIRTY` request across a park, a copy's wait, two jobs'
requests, a waiter killed while parked, two cycles, the same port back.

| Id | Rule | Case (stage 9, `rebind`) | Control |
|---|---|---|---|
| L.object.300 | `PAGER_KEEP`: `PAGER` on the pager, one per pager, `Rights::KEEPER`, one object charged to the caller | a second keep `ALREADY_BOUND`; rights read exactly; the job's objects rose by one | K13-C1: a second keeper made |
| L.object.301 | With a keeper the pager's close ends no request, and a request opened while parked is listed, unsent | a client faulting across the close stays waiting; a fault while parked likewise, no packet | K13-C2: the close ends them (the K3 path) |
| L.object.302 | `PAGER_TAKE_UP` needs `MANAGE`, refuses a live pager, re-sends each open request on the new port with its id; the client's access then succeeds | packets read from the new port with the old ids; supply by the new handle; the client's load returns the bytes | K13-C3: not re-sent, the client times out and the check fails |
| L.object.303 | A parked wait stays bounded by the pager's bound | bound 5 ms, no take-up: ends never before and within 5 s, `SIGBUS` | K13-C4: the deadline ignored while parked |
| L.object.304 | The keeper's close while parked is the pager's death; while live it changes nothing | waiter ended at once; live case keeps serving | K13-C5: close leaves them waiting |
| L.object.305 | Requests' charges stay the faulting job's across park and take-up | the job's memory holds the record | K13-C6: the record uncharged |
| L.object.307 | Dirty pages stay reported to the next instance | `PAGER_QUERY_DIRTY` from the new handle | K13-C7: the query empty for a kept pager |

In `object/pager_check.rs`'s `run_rebind` (raised, its harness; H.OBJ.28 and L.object.300-305 on
`raised_only` until the check host, 5968 (8)), on every boot on three architectures, every call through the entry. Controls
through `gate.sh control --expect`, FIRED (panic), x86-64 KVM.

## 4. Questions

* **Q1** No generic kernel service object: the supervisor's duplicates are the channel and VMO
  half of "one generic contract". Recommendation: yes; OPAQUE-KERNEL's in-kernel generic contract
  was for kernel-side state, and a user-space server has none but this.
* **Q2** The bound not restarted at take-up. Recommendation: yes: H.MEM.22 reads per wait.
* **Q3** A `PACKET_PAGE_REQUEST` carrying a ticket once K3's slice B lands: the ticket is the
  request's, so it survives; adoption through the new pager handle. Recommendation: as written;
  slice B's check adds the case when it lands.
* **Q4** M8's row ("a kill-and-restart row per server on K13") is where the end-to-end evidence
  comes; K13's own is the boot check. Recommendation: yes.
