## 1. What it is

A **region** is a partition's shared half: an address space holding `linuxd`'s
code, data and heap (K2's space object), and the partition's **shared handle
table**. Each Linux process is a kernel process of that region: its own restricted
space, its own **private handle table**, its own job, and the region mapped above
the restricted space. Which table and which half a call reaches is decided by the
mode the call came from, never by an argument.

The process's threads run in normal mode (`linuxd`'s code, the region and the
restricted space in reach, the shared table) or in restricted mode (the program's
code, the restricted space alone, the private table). K1 is how they go between.

## 2. The interface

### 2.1 The window

| | x86-64 | AArch64 |
|---|---|---|
| Restricted space | `[MMAP_MIN_ADDR, SHARED_BASE)` | the same |
| `SHARED_BASE`, `restricted::SHARED_BASE` | `0x7000_0000_0000` (root slot 224) | `0x7000_0000_0000`: `USER_VIRT_END` is `0x8000_0000_0000` on both |
| Shared region | `[SHARED_BASE, USER_VIRT_END)`, 16 TiB | 16 TiB |

A restricted space's ceiling is `SHARED_BASE`, set as the space is bound, and no
call raises it. So a Linux program's `mmap` window is 112 TiB rather than 128: what
`linuxd` hands out is `linuxd`'s, and programs learn the top from `linuxd`'s auxv
and stack, not from a constant. The shared region is a window of the same space a
program's would be, with its own floor (`SHARED_BASE`).

### 2.2 The calls

| Number | Call | Arguments -> result | Needs |
|---|---|---|---|
| 0x1097 | `REGION_CREATE` | `(job, *space: u64)` -> region handle, `Rights::REGION` (`MANAGE`, `DUPLICATE`, `TRANSFER`); the region's space handle in `*space`, with `Rights::SPACE` | `MANAGE` on `job`, under `may_start_in`; one object charged to it. Every process of the region is in `job` or a descendant |
| 0x1098 | `PROCESS_CREATE_SHARED` | `(region, job, space, name: *const u8, name_length, *out_space: u64)` -> process handle, `Rights::PROCESS`; a handle to the process's restricted space in `*out_space`, `Rights::SPACE` (K2), or 0 if `space` was given | `MANAGE` on the region and on the job, the job within the region's and `may_start_in`. `space` is 0 for a fresh space, or a handle with `MAP`, `READ`, `WRITE` and `TRANSFER` from `SPACE_CREATE` or `SPACE_CLONE`, consumed: **that is `fork`**. A space already bound to a process, or a region's, is `BAD_STATE` |
| 0x1099 | `THREAD_CREATE` | `(entry, stack, argument)` -> thread handle, `Rights::THREAD` (`SIGNAL`, `WAIT`, `READ`, `DUPLICATE`, `TRANSFER`) | **the caller's own process only**, so `MANAGE` on a process never lets its holder run code inside it. Refused from restricted mode. A new Linux process's first thread comes from `PROCESS_START_SHARED`. In a process of a region the entry and stack lie in the region (`INVALID_ARGS` otherwise); elsewhere in the user half; the job's task quota, charged as a thread's is |
| 0x109F | `THREAD_SELF` | `()` -> thread handle, as above | any thread, in the table its mode names: how a process's first thread comes to be kicked. Refused from restricted mode |
| 0x109A | `THREAD_EXIT` | `(status, whole_process: bool)` -> never returns | normal mode, or a native process; refused `BAD_STATE` from restricted mode, where the program's `exit` is a Linux number and `linuxd` ends it. Ends the calling thread, or its process with `status`. The native ABI's own: `exit_group` is the Linux personality's, which `personality=user` has none of |
| 0x109B | `HANDLE_TO_SHARED` | `(private: handle, rights, options)` -> shared handle | normal mode of a shared process; the handle in **this process's** private table, holding `TRANSFER`; `rights` a subset of its rights. The private one is gone, unless `options` has `KEEP`, which needs `DUPLICATE` too and leaves it: `PORT_FD`, which only borrows its port today, uses `KEEP` |
| 0x109C | `HANDLE_TO_PRIVATE` | `(shared: handle, rights)` -> private handle | the same the other way, no `KEEP` |

M5-LIFT's 0x10B1 to 0x10B3 (`PROCESS_EXIT`, `THREAD_CREATE`, `THREAD_EXIT`) are
withdrawn in favour of these. On ARMv7-A these calls answer `NOT_SUPPORTED`.

A process of a region starts with **0x109E `PROCESS_START_SHARED`**
`(process, entry, stack, bootstrap)` -> 0, `MANAGE` on the process: its entry and
stack lie in the region, the thread starts in normal mode, and the bootstrap handle is
moved to the **shared** table with its value in the first argument register. K15's
`PROCESS_RUN` is the same call for a process of no region. K17's level is an option of
`JOB_CREATE`, so it takes no number of this block.

**Who has what handle**:

* Any holder of a space handle reaches what K2 gives it. The region's space handle
  is how `linuxd`'s first image gets mapped: the creator (the partition manager,
  §5 of the plan) maps `linuxd`'s segments with `SPACE_MAP`, and the EXECUTE right,
  then `PROCESS_CREATE_SHARED` and `PROCESS_START`.
* `linuxd`'s own running code holds the region's handle in the shared table, given
  to it as its bootstrap's, and creates every Linux process with it.
* The new restricted space's handle is how the program's image gets mapped, under
  K2's rule: **no wider than that handle's rights** (the row's "the creating
  `linuxd` gets no handle into the new process's restricted space beyond K2's
  rights on it").
* `SPACE_CLONE` of the region's space is refused `NOT_SUPPORTED`: nothing forks the
  region. `SPACE_CLONE` of a restricted space is `fork`'s, as K2 has it.

### 2.3 What the mode picks

| Asked in | Restricted mode | Normal mode of a shared process | A process with no region |
|---|---|---|---|
| A handle's number | the private table | the shared table | its table |
| The address a pointer argument names | the restricted space only | below `SHARED_BASE` the restricted space, at or above it the region | its space |
| `VMO_MAP`, the call's "own space" | the restricted space | the region | its space |

These answers are one function each (§3), and **no call takes the table or the
space as an argument**, so `linuxd` holding a handle number a program made means
nothing, and the reverse. `PROCESS_GIVE` puts a handle in the **target's private**
table, and `PROCESS_BOOTSTRAP`, in normal mode, takes it into the **shared** one.

**Across a shared process's two tables** only §2.2's two calls move a handle. K1
calls `PORT_FD` an exit: `linuxd` receives `(port)`, a number in the private table,
calls `HANDLE_TO_SHARED(port, rights)` and builds its fd on what comes back.

## 3. Two roots

Each process of a region has:

* its **restricted root**: the space's own root (`AddressSpace::root`), the kernel's
  half, the restricted window; nothing else. It is the only root that holds a mapping
  the restricted space made.
* its **normal root** (`AddressSpace::unified`, a second frame, allocated at
  `PROCESS_CREATE_SHARED`, charged as a table): the kernel's half, the same
  restricted slots, and the region's slots.

**The region's slots never change.** At `REGION_CREATE` a table is allocated for each
root slot of `[SHARED_BASE, USER_VIRT_END)` (32 pages), and they are never freed
before the region ends. A normal root copies those root entries once, as it copies
the kernel's half (`prepare_user_root`), and every region mapping is below them, so
a mapping appears in every process of the partition with no root to update. So the
region's mapping cost is the mapping's own; and the shootdown goes to the region's
`cpus` (below).

**The restricted slots are kept in step.** `Mapper::prune` frees a table whose last
entry went, the top level's included. A restricted space **keeps its top-level
tables** (`Mapper::keep_top`, this space's flag alone, a process without a region
behaves as before): so a root entry goes from absent to one table once, and never
back. A normal root copies a slot as a fault finds it absent: a fault from normal
mode on a restricted address first runs `AddressSpace::sync_top(address)`, copies the
one entry under the space's lock if the space has it, and goes on as any fault. So a
slot's cost is one fault per process, the restricted root's path is untouched, and
no stale entry can name a freed table. That rule is `L.user.180`'s check: a space's
restricted slots are a subset of a normal root's, bit for bit, or absent, and a
negative control lets a top-level table free and fires.

**At a thread switch** `swap_address_space` keeps today's rule (one `Arc` compared),
and then for a shared process installs the root its next task's mode names (one more
comparison, to a per-processor record of the root this processor holds). A flip is a
root write and that comparison: no join, no leave, no lock.

**TLB**: the space's and the region's shootdown sets (`AddressSpace::cpus`). A
processor joins the restricted space's set at a switch, as today, and **also the
region's**, and leaves at a switch away. A flip changes neither. So a region mapping
change reaches every processor that may hold it under any process of the partition,
and a restricted space's reaches every processor running that process in either mode.
On a processor without PCID a root write has dropped everything non-global, so a flip
is safe. With PCID, the normal root has its own id (a second `pcid` key): a flip to
it passes `space.begun + region.begun`, so a change of either forces its flush at the
next flip. Its check is `pcid::check`'s slot rule, on both keys.

**`speculation::entered_space`** is given the restricted root, always (K1 §6).

**A mistake here can only make less reachable**: restricted slots are copied only
from the restricted root and region slots only from the region. **No code path writes
a region entry into a restricted root**, and the mapping sweep (K1 §10) proves it on
each boot, with a negative control that plants one.

## 4. How the calls find it

* `Process::region: Option<Arc<Region>>`. Today's `with_handles` becomes
  `with_handles` by mode: the running task's mode byte (the caller is always the
  running task on those paths; a walk of another process's table goes through a
  second, explicit `with_private_handles`, which `PROCESS_GIVE`'s target is). A
  process without a region reaches one table by one branch.
  `try_with_handles_masked` is the same, and `Key::new` for `ADDRESS_*` (K5) keys on
  the routed space. `mark_vectors_dead` on the fast branch is not raised from
  restricted mode. `process.space()` is **renamed**, so that the compiler visits each of
  its forty sites and each says which it means: `caller_space()` or `restricted_space()`.
* `AddressSpace::route(address) -> &AddressSpace`, in `user::space`, is the one place
  the mode picks a space, for §2.3's second row. `uaccess`'s page loop and
  `resolve_user_fault` call it. Only the running task's own space is routed: a
  by-handle `SPACE_READ` names its own space and goes straight there.
* `Process::caller_space()` is §2.3's third row, for "the caller's own space" in
  `native.rs`: the three sites that map into the caller.
* The `Host` question: a shared process's `Host` is the core's own implementation
  (`object::process::Bare`, **new**: it exists on no branch yet, or K15's if that lands
  first), which answers every question the core asks and holds no Linux state, so no
  personality runs for it in any build. The trap's return path therefore asks the
  process, not the registered personality, about a kill, so that such a process sees
  its kill and a fault of its goes to K1's or K4's paths instead of the "no personality"
  panic. On a kernel with `personality=kernel` a shared process makes no
  Linux call in the personality from restricted mode (K1), and from normal mode a
  Linux number answers `ENOSYS`.

## 5. The ends

A region lives as long as a process or a handle names it. As the last goes, the shared
table's handles close, its tables and frames go. A process that ends closes its private
table, and leaves the region's alone. **The cycle**: a shared table can hold a handle
to its own region (`linuxd` does), so a count alone would never end it. The closing
rule: a process holds the region strongly, a region handle does too, and when the
region's process count falls to zero its shared table is emptied, whatever handles
are in it, which drops any region handle inside it; a region handle held outside keeps
only the emptied region, and `PROCESS_CREATE_SHARED` on one is `BAD_STATE`. **A `linuxd` that dies takes its partition with
it** (K13's row): `linuxd` is many processes' normal-mode code, one bug is all of them,
and the job above kills them. The mechanism adds nothing for that; the kernel's rule is
the job's.

## 6. `exec`'s swap

K2 §2.2 leaves "the swap that binds a space to a process" to K11, and K2 also allows an
in-place exec with `SPACE_UNMAP` over the window. **The first landing is the in-place
one**: `linuxd` unmaps the whole window after the point of no return and maps the new
image, as `empty_user_half` does. A bind (`PROCESS_BIND_SPACE`, kept as a number at
a number allotted then) lets `exec` fail cleanly later
than the point of no return, and is a later landing with its own review.

## 8. Checks and controls

A stage 9 check (`check_regions`, `FX-0925`, line `regions`), and a native program,
`restricted-check`, shared with K1 §10:

| Case | What is checked |
|---|---|
| Two processes, one region | each writes a word in the region through its own process and each reads the other's; neither reaches the other's restricted space (each `FAULT`, K2's rule); their restricted spaces are their own at the same address |
| Tables | a handle in the shared table's number from restricted mode is `BAD_HANDLE`, and the reverse, on the same number with different objects, and each answers its own |
| Moves | `HANDLE_TO_SHARED` without `TRANSFER`, with wider rights, of a number not in the private table, from restricted mode: each refused; a good one is gone from there |
| Mapping | a page mapped in the region after the second process started is seen by both; an unmap is seen by both (the shootdown, on a second processor with `--smp 2`) |
| Pointer routing | a `channel_write` from normal mode with a buffer in the region, one with a buffer in the restricted space, each copies right; from restricted mode, a buffer at a region address, `INVALID_ARGS` |
| A kill | killing a process leaves the region and the other process running; killing the job above takes all; frame, table and object counts back where they were |

Controls: (a) `with_handles` takes the table from an argument the caller sets: tables
fires. (b) `Mapper::keep_top` left off: a top table freed under a normal root's slot,
`L.user.180`'s check fires. (c) `prepare_user_root` of a restricted space also copies a
region slot: the sweep fires. (d) `route` stops looking at the mode: the pointer case
fires. (e) Skip joining the region's set: the mapping case fires on two processors.
