So K8's new code is small: **an explicit bind, by a right only devmgr holds, and
a refusal when there is none**, plus requirements and controls for the two facts
that today hold by accident of order or without a stated rule. `DEVMGR_START`'s
removal is in the retired-calls landing (`MICROKERNEL.md` §3), not here.

G8 of `DRIVER-MODEL.md` §2 (`input_functions` by xHCI class, `intel_gpu` by
vendor and class, `reads_log`, `may_have_client_nodes`) is the kernel's remaining
matching. §5 says what happens to each.

## 2. The mechanism

**`Rights::BIND_DOMAIN`** (bit 13; bit 12 is left for another stream's use of
the shared file). The kernel mints it on one handle of each pair, the one
devmgr keeps, and only in a kernel with explicit nodes
(`KEPT_DEVICE_RIGHTS`; compile-time assertion). `KEPT_DEVICE_RIGHTS` carries
`DUPLICATE` and `TRANSFER`, and narrowing to a driver's `DEVICE_RIGHTS` is
devmgr's act in ring 3, so "no driver ever holds it" is **not** the kernel's to
prove. V-20 states that residual. A kernel refusal to transfer it is not asked
for (K8.1).

**`DEVICE_BIND_DOMAIN` (0x10C0): `(device)`**, needing `MANAGE | BIND_DOMAIN`.

* It attaches the function to a domain **the kernel makes and keeps**, the
  machinery of `DeviceNode::domain()`. It takes no domain id and answers none. No
  call names a domain, a unit, a table or a context entry.
* A node that reaches no memory, or a function `iommu::dma_exempt` names, answers
  `WRONG_TYPE` (not a rights refusal, so no false RIGHTS record; K8.7).
* **A domain that would not translate is refused `ACCESS_DENIED`, and not kept,
  unless the boot carries `ferrix.unisolated` (K8.3).** The DMA gate `L.device.58`
  is in devmgr, which is uncertified and whose confinement is the IOMMU; an
  untranslated function is not confined by it, so for explicit nodes the gate's
  floor moves into the kernel. D6, if the customer ever approves it, returns here.
* A function whose only possible domain is held (`domain_for` answers `None`, an
  RMRR identity domain) answers `LIMIT_REACHED` (K8.5).
* A node already bound answers `ALREADY_BOUND`, nothing changed, and **devmgr treats
  that as success**: a restart (`DEVMGR.md` §4, T0) and `ferrix.intelgpu`'s boot-time
  domain both meet it (K8.4). A bound node stays bound for the machine's life: its pin
  budget and quarantine are the domain's. A quiesce turns bus mastering off, not the
  binding.
* A refused node answers `BAD_STATE`, as every `MANAGE` call does.

**Explicit binding per node.** `DeviceNode.explicit_bind`, from
`EXPLICIT_BIND = cfg!(ferrix_personality = "user")` at construction, is changed only
by the boot check while checks run. Under it, **an aperture (`IO_MAPPING_CREATE`), a
vector (`INTERRUPT_CREATE`) and a pin refuse `BAD_STATE` while unbound** (K8.2), and
no native path makes a domain.

**Every caller of `domain()`, listed (K8.5).** Native paths, which go through
`domain_for_call` and never make one on an explicit node: `pin_through`,
`device_set_limit`, `domain_then_dma`, `device_isolation` (an unbound node answers
untranslated), `may_have_client_nodes` (the side effect it had is gone on explicit
nodes). Kernel paths, which keep `domain()`: `iommu::announce_intel_gpu` (boot, the
GPU's budget before any pin) and the check paths (`object/check.rs`,
`object/pin/check.rs`, `device/check.rs`, `chardev/check.rs`,
`give_check_domain`).

**Which node is which, by profile.** `personality=user`: every node published is
explicit and DEVICES says so (`FLAG_EXPLICIT_BIND`, in the flags' host test).
`personality=kernel` (`present`, `desktop`): none, `KEPT_DEVICE_RIGHTS` carries no
`BIND_DOMAIN`, the flag is clear and devmgr's new branch is not taken. The call is
compiled in every profile so its check runs in the reference configuration (accepted,
K8.8). In `present` no process can hold the right.

**A function firmware left mastering** (K8.6): at an explicit publication,
`silence_found_masters` turns its bus mastering off; one whose switch cannot be
reached is refused. A bridge is left alone (`check_dma_switch`'s reason).

**devmgr.** Under the flag it binds on its kept handle first (`bind_first`), then
asks `device_isolation` and runs the admission, whose line says any refusal.
`ALREADY_BOUND`, `WRONG_TYPE` and `ACCESS_DENIED` go on to the admission (the last to
be refused there, on its line); any other refusal is a driver not started. A
function the gate refuses is left bound: its domain is empty, and no driver is given
it.

**The safety partitions' devices** are not in DEVICES at all under `personality=user`
once a partition description exists (`BOOT-AUTHORITY.md`). A node handed to the
partition manager is explicit too, with the same right.

## 3. Rules and requirements

**H.DEV.9**: *the kernel mints the right to attach a function to an IOMMU domain only
on the kept handle of a device's pair, and no call names, passes or maps an IOMMU
domain, unit or table.*

**H.DEV.10**: *under explicit binding an aperture, a vector or a pin is given only
after the node was bound by the holder of that right, and a PCI function becomes a bus
master only after that bind; a Tree or VirtioMmio node has no master enable, and its
limit is the refusal of those three (K8.2).*

**H.DEV.11**: *IOMMU registers and tables are in no aperture.*

| Id | Rule | Check | Control (`gate.sh control --expect`) |
|---|---|---|---|
| L.device.66 | `DEVICE_BIND_DOMAIN` needs `BIND_DOMAIN`; `MANAGE` alone is refused `ACCESS_DENIED` | `object::authority_check` (stage 10): a made-up node refused | the test removed: *a device handle without BIND_DOMAIN bound a domain* |
| L.device.67 | the kernel mints `BIND_DOMAIN` on the kept handle alone: `GIVEN_DEVICE_RIGHTS` and `DEVICE_RIGHTS` exclude it | compile-time assertion | the constant widened: the build fails (`--expect-host`) |
| L.device.68 | on an explicit node, aperture, vector, pin and set-limit refuse `BAD_STATE` while unbound, isolation answers untranslated, and none makes a domain | made-up node, each call | `domain_for_call` answers through `domain()`: *a pin on an unbound node made a domain* |
| L.device.69 | a bind on a bound node, a no-DMA node or a refused node is refused, nothing changed; `domain_for` answering `None` answers `LIMIT_REACHED` (read, not reached on QEMU: argued) | each in turn | each refusal removed in turn, its own text |
| L.device.70 | no aperture overlaps an IOMMU unit's registers | `device::check::check_iommu_held`: every unit reserved, a made-up mint over it withheld, a sweep of every published aperture | the units left out of `Reserved`: *an IOMMU unit's registers are not reserved* |
| L.device.71 | `BIND_DOMAIN` on kept handles iff `personality=user`, and each node's rule follows | assertion, plus every published node read | a node forced: *a node's binding does not follow its profile* |
| L.device.72 | a bind whose domain does not translate is refused and not kept without `ferrix.unisolated` | made-up node, without and with the word | the test removed: *an untranslated function was bound without the opt-out* |
| L.device.73 | no published aperture lies over the memory map (where the units' tables are), the boot framebuffer's lent node aside | the same sweep | `Reserved` without the map: *a published aperture lies over the memory map* |
| (H.DEV.10's master half) | a real idle PCI function: not a master after a refused pin, nor after a bind alone; a master after a pin | `borrowed_function`, on any idle function; edu on x86_64 where it is first | the bind's test removed from `domain_for_call` above |
| **restart row** (K8.4) | a second `bind_domain` answers `Already` and changes nothing; `bind_first` goes on | check, and devmgr's `test-init` restart under `personality=user` once it boots | -- |

Existing rules this design **names and does not change**: `DEVICE_CONFIG_WRITE`'s
mediation, `verify_config`, `keep_ats_off`, `enable_dma`'s `dma_exempt`, the DMA gate
`L.device.58`, `H.DMA.*`.

**Audit (K8.7).** `record_call` audits every `ACCESS_DENIED` as RIGHTS, so a bind
refused on the right or on an untranslated domain writes that record, as a refused
pin does. A successful bind writes none (Q2): it grants nothing until a driver pins.

## 4. Where it is exercised

`present` compiles and runs the check at stage 10 on a **made-up node** the check
builds itself (the `device/generic_check.rs` pattern), with `Explicit` set and a
handle in the check's own table. `personality=user` adds the real path, proved by
`test-boot` of that kernel once §5's boot exists: every driver bound by devmgr on
a line of its own. Until then the real path has no boot; it is compiled and
reported as owed (`docs/BACKLOG.md`).

## 6. What it does not do

* It does not let devmgr choose a domain's shape, share a domain between
  functions, or move a function between domains. Today's one-domain-per-node
  stays. A shared domain (a multi-function device whose functions DMA to each
  other) needs its own review: **Q1**.
* It does not make devmgr certified. devmgr's binding a function to its domain
  grants the function nothing: the domain is empty until a driver pins, and a pin
  is limited by the VMO handles the driver holds. So a lying or compromised devmgr
  can start a driver on the wrong device (the existing residual, `L.device.58`'s
  V row) but cannot widen a device's reach through this call. That is the argument
  for leaving devmgr uncertified (§6.3 of `MICROKERNEL.md`), and **V-20** states it.
* It does not change the DMA gate.
