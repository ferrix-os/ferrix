## Where it stands

Ferrix boots interactively on the real N150 box (SOYO M4 Pro): hyprix desktop on the
firmware framebuffer, terminal takes the USB keyboard, / is btrfs on the SATA drive
(installed at first boot), yt6801 link up 1 Gbit, internet works: `gryphlink` starts under
Wine and shows the launcher with its online notices. Not logged in, nothing downloaded.

Facts learned about the box (docs/N150.md still assumes otherwise; fix it at landing):
* The drive is SATA (PELADN 512GB, serial 20250522101772, AHCI 8086:54d3 at 00:17.0), not NVMe.
* The firmware has NO UEFI network stack: the netboot stick cannot work (iPXE lists no card).
* No serial port output reaches anyone (COM1 exists, its TX interrupt never comes).
* MSI never arrives (xHCI, yt6801): both drivers poll (usbhid every 8 ms, yt6801 every 250 ms).
* Firmware leaves 9 endpoints' memory decoding off; GOP framebuffer at 0x4000000000, BGRx.
* AMI firmware hangs in ExitBootServices if memory of an OS-defined type exists.
* The keyboard 1a2c:2124 resets itself (USB disconnect) after ~10 unserviced reports
  (reproduced on Linux by unbinding usbhid).

## The boot card (how to test on the box without Ubuntu)

The scripts are in tools/common/n150/card/ on branch n150-handover (to-card.sh, make-card.sh,
write-card.ps1; box-go.sh and box-esp.sh are the Ubuntu-live scripts served on :8150).
They hardcode the Windows PC's paths (G:/GameLab/iso/ferrix, F:/Dokumente/projekte/os,
card drive H:); adjust them on another PC.

32 GB microSD in a USB reader. MBR + FAT32 `FERRIXBOOT` (Windows drive H:), holding
EFI/BOOT/BOOTX64.EFI and FERRIX/{KERNEL.ELF,INITRD.IMG,CMDLINE.TXT,DEFAULTS.TXT}.
Card holds build 5fe416ad6 (keyboard works), DEFAULTS.TXT = desktop mode
`ferrix.checks=skip ferrix.efifb ferrix.fbcon` (log mode: `ferrix.checks=skip ferrix.fbcon
ferrix.fbcon.small`; copy kept as G:/GameLab/iso/ferrix/card/DEFAULTS.TXT.with-efifb).
New build onto the card, from Git Bash on the Windows PC with the card in:
`bash /g/GameLab/iso/ferrix/card/to-card.sh <commit> H` (builds on nazuna in worktree
.claude/worktrees/win-n150-esp with ~/target-n150-esp; about 1-3 min).
The firmware keeps putting the SATA drive first: boot the card from the boot menu each time,
or update the drive's ESP too (the drive's ESP still has the 15adb7a0f loader+kernel).
