Session os-76 planned the route from about 870 ns to under 400 ns for
`domain-call`. The product owner, os-85 (po10-win), runs the agents that
build the cuts; os-76 owns the measurement (P0) and the fast path v2 design
(P2). This file says where both stand at the wind-down of 2026-10-07.

  All three were applied by about 23:45 (customer's sudo): from then on, core 11's
  figures are taken at full boost.

## What was measured (window 1, 22:49 to 23:02, quiet host)

Host `perf` on the vCPU thread, guest-mode events per round trip, on
`main`'s code in the fast clock mode:

| | value |
|---|---|
| `domain-call` | 858 to 868 ns |
| cycles | about 4,840 |
| instructions | about 4,980 (IPC about 1.0) |
| iTLB / dTLB walks | 6 / 6 |
| return / other mispredicts | 10 / 15 |
| `null-entry` (entry and exit only) | 23 ns a call |
| `null-general` (general path to decode) | 131 ns a call |

Findings:
- **The two boot modes are the CPU clock.** The cycles per trip are the
  same in both; core 11 runs at about 4.6 GHz against 5.6.
- **Guest RAM on hugetlb pages changed nothing.**
- **The unwind ablation** (`os76/unwind-abl`, timing only) left cycles,
  instructions and return mispredicts unchanged. §9.12's G1 premise, that
  the woken task's unwind mispredicts, is false.

All of this is in the skill's §2, §5 and §7 and in the data file's `tried`
entries.

The cost is instructions: about 2,500 a direction against a few hundred
for seL4's fast path.
